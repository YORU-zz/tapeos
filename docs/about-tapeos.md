# TapeOS について

この文書は、TapeOS の使い方（マニュアル）でも契約（インターフェース
仕様）でもなく、TapeOS というもの自体について――何を再現し、
どういう考え方で作り、どこへ向かっているか――をまとめたものです。

## TapeOS とは何か

TapeOS は、カクヨム連載小説『還暦間際のオッサンが8Bit時代に戻って
不完全燃焼をやり直す話』（辺根除音 氏）に登場する架空の OS
「OUROBO/ROS」の前身として描かれた、テープ時代のシングルタスク OS
です。作中での自己評は「機械語モニタ＋α」――メモリを覗き、プログ
ラムを読み込み、実行するための最小の土台に、ファイルとメディアの
扱いを少しずつ足していった OS です。

本プロジェクトは、その TapeOS を実在の 8 ビット PC の上で実際に
起動して使える形で再現しています。本リポジトリで公開しているのは
Sharp X1 版で、プロジェクト内には MZ-80B／MZ-80K 版と PC-8801 版
も存在します。

## 全体像

TapeOS は、モニタシェルを中心に次の層でできています。

- **シェル**：起動して最初に対面するモニタです。メモリ操作、
  プログラムのロードと実行、メディアの初期化などを行います。
- **IOCS**：アドレス固定のジャンプテーブル経由で呼ばれる入出力
  インタフェースです。上層のプログラムは機種差を IOCS の裏側に
  隠して書けます。
- **メディア層とファイルシステム**：FD、カセットテープ、EMM 上の
  RAMDISK を扱います。ファイル形式は TOSD（本プロジェクトの
  ディスク形式）です。
- **言語処理系**：TinyBASIC（コンパイラと JIT インタープリタ）、
  SmallC（C サブセットのコンパイラ系）、Tiny Scheme（単体版と、
  他言語から呼び出せる埋め込みコア）が同居しています。
- **道具群**：テキストエディタ 2 本、アセンブラ 2 本、逆アセンブラ、
  3 形態のデバッガ、Markdown ビューワーなど、OS の上で暮らすため
  の道具一式です。

OS 本体だけでなく「その上でプログラムを書き、動かし、直す」まで
をひとつの環境として作っているのが、この再現の形です。

## 設計の考え方

- **原作再現と味付けを分ける**：原作に根拠のある再現と、再現側の
  判断で足した要素（味付け）は、文書と実装の両方で区別して明示
  します。混ぜて「再現」とは言いません。
- **制約は時代のまま受け入れる**：当時の制約は、現代の感覚で
  便利に直すのではなく、まず時代の形で成立させます。たとえば
  ファイル名は格納時に大文字化されます。これは当時の他 OS
  （CP/M や Hu-BASIC 等）では小文字のファイル名が通用しなかった
  ことと揃えた、時代考証としての仕様です（詳細はインターフェース
  仕様 §3.4）。
- **本体は小さく保つ**：シェル常駐部には厳しいサイズ上限があり、
  入り切らない機能はディスクプログラムへ分離します。小ささは
  制約であると同時に、この時代の OS の性格そのものだと考えて
  います。
- **差異は境界で吸収する**：他の OS や形式との違い（ファイル名の
  規則、形式の差異など）は、本体側の仕様を曲げて合わせるのでは
  なく、境界に置いた層（形式層と互換ラッパー）が吸収します。
  後述の 2 段階 OS もこの考え方の延長です。
- **契約と検証で守る**：上層が依存してよい約束はインターフェース
  仕様に集約し、契約チェックと全スイートの監査（回帰試験）で
  変更のたびに確認します。公開物のバイト同一性も検証対象です。

## 段階とこれから

TapeOS は、作中の系譜と同じく発展の途上にあります。

- 現在は「テープ時代の OS」に、FD と RAMDISK のファイル環境が
  実用になった段階です。
- ファイルシステムの拡張（空き領域の再利用とディレクトリ拡張を
  入れた OUROBO/DOS Filesystem ver.0）で、DOS と呼べる段階へ
  進みます。
- その先には、TapeOS を第 1 段として S-OS や CP/M を互換レイヤ
  経由で載せる「2 段階 OS」、さらに作中の OUROBO/DOS、そして
  リアルタイムカーネルを持つ ROS 世代が構想として続いています。

本リポジトリはその過程の暫定版（先行公開）で、再現プロジェクトの
完了後に本公開へ移行する予定です。

## 検証について

検証はエミュレータ上で行っており、**実機での動作は未検証**です。
この点は隠さず、実機で試された方の動作報告を歓迎しています。
検証の方法と結果は `docs/audit.md` に、原作との技術的差異の
根拠は技術解説シリーズ（`docs/tech/`）にまとめています。
