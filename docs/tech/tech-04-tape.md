# 技術解説04：テープ層

## 役割と設計

テープ層は、カセットテープへのプログラム保存と読込を担います。シェルの T（読込）／S（保存・新規）／A（追加保存）と、IPL の CMT ブートが使う経路です。

設計の要は、論理形式と物理層の分離です。プログラムの並び方（情報ブロック＋データブロック）という論理形式にはタイミング情報を一切含めず、速度や変調の違いは物理層だけの差し替えで吸収します。この分離があったため、後からの 4800bps 化や WAV 相互運用は、論理形式を変えずに物理層と容器の追加だけで実現できました。

論理形式の情報ブロックは、実在の HuBASIC ヘッダと共通の32バイト形式を採りました（tech-03 の §3.5 と同一）。互換 IPL がそのまま読める形であり、ブート用ヘッダとテープ用ヘッダを1つの形式に統一できます。

## 実装の要点

- 論理形式：テープはプログラムの列で、各プログラムは情報ブロック（32バイト。名前13バイト空白詰め・大文字、拡張子は全機種 "Sys" 固定、サイズ／ロードアドレス／実行アドレス）＋データブロックです。情報ブロックにはバイト和（LE16）のチェックサム2バイトが付きます。データブロック側にチェックサムはありません
- シェルの T は、情報ブロックのロードアドレスへデータを読みます（実行アドレスはシェルでは使いません）。名前を指定すると、一致しないプログラムを読み飛ばして探します
- X1 物理層：バイトは スタートビット "1"＋8ビット MSB ファースト で送ります。情報ブロックのリーダは "1"×800、"0"×40、"1"×41、データブロックは "1"×800、"0"×20、"1"×21 です。`.cmt` ファイルは生のパックドビット列そのものです
- X1 クラシックのタイミング：ビットは立上り後 約185µs のレベルで判定し、書込波形は "1"＝High 約380µs＋Low 約280µs、"0"＝High 約100µs＋Low 約280µs です。実効は約1,738bps でした
- MZ 物理層：標準 MZ 形式です。情報ブロックは128バイトの MZ ヘッダとして2回送り、両コピーを検証・相互照合します。バイト形式は X1 と違い末尾ビット "1" が付きます。データのチェックサムはポップカウント（全データの1ビット数の合計）で、情報ブロックのバイト和とは別規約です。物理層そのものに X1 との直接互換はなく、「統一」とは論理内容の統一を指します
- MZ リーダの較正：固定閾値を廃し、各セクション頭のロングマーク（"0"×10000）の中で較正します。相互に近い周期を24個集めてソートし、75パーセンタイル×1.5 を閾値とする方式で、1つのリーダがクラシックと 4800 の両方をモード切替なしで読みます
- 4800bps 化：X1 はコア側のタイミング表切替（環境変数 `XMIL_TAPE_BPS=4800`）＋幅形式リーダ（立下り同期→立上り待ち→約+65µs 遅延後に1回サンプル）で読み書きとも達成しました。MZ-80B も読み書き達成、MZ-80K は書込のみ達成で、読込は本環境では未達（制約として記録）です
- WAV 相互運用：相互運用の正規形式は WAV です。コアは固定しきい値だけでデジタイズし（決定論を守るため汚れ対策を入れません）、DC オフセット・極性反転・レベル変動への対処はホスト側ツール `wavclean` が担います。正規 WAV の定義（48000Hz／16ビット／モノ／±12000 の矩形波）をコア録音と wavclean で共有するため、同じビット列に対する両者の出力はバイト同一になります

## 原作との技術的差異

- 4800bps の変調方式：作中の方式は「サッポロシティスタンダード方式を参考に H/L 独立で変調する」ものですが、再現側の変調方式は作中方式ではありません（tape-4800.md が明記しています）。作中に合わせたのは到達点——標準の4倍が3機種共通の標準フォーマットになること（第17話〜第19話）だけです
- クラシック速度の公称値：作中では標準＝1200bps が前提ですが、再現側クラシックの実効は約1,738bps で、公称 bps の明記は再現側資料にもありません（interface-spec §4.4）。タイミングの絶対値はエミュレータ環境の実測に基づきます
- IPL の CMT ブートと 4800：互換 IPL ROM は古典速度固定の第三者成果物で、変更しない方針のため、4800 テープからはブートできません。4800 の主経路は FDD 起動後の IOCS テープです（負の対照で確認済み）
- 9600bps：作中では X1／MZ-80B のオプションとして 4800 と併記されますが、再現では対象外・未検証です
- MZ-80K の 4800 読込未達：DATAREC の耳信号再現が 4800bps・2MHz では不安定で較正が漂うためで、エミュレータ環境側の制約です

## 数値まとめ

- 情報ブロック：32バイト＋チェックサム2バイト（論理形式、全機種共通）
- X1 クラシック：実効 約1,738bps、リーダ "1"×800／"0"×40／"1"×41（情報）、"1"×800／"0"×20／"1"×21（データ）
- 4800 変種の実効：X1 約5,279bps、MZ-80B 約4,185bps、MZ-80K 約3,812bps（書込のみ）
- MZ ヘッダ：128バイト×2回送り、データチェックサムはポップカウント2バイト
- 正規 WAV：48000Hz／16ビット signed／モノ／矩形波 ±12000
