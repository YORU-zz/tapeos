# 技術解説10：シリアル／RS-232C

## 役割と設計

シリアルは、TapeOS と外部（ホストやもう1台のターゲット）をバイト列でつなぐ経路です。原作第75話の X1 用 RS-232C ボードを再現し、エミュレータコア側に Intel 8251 USART のレジスタモデルを持ち、ホスト側は PTY へ橋渡しします。二層デバッガ（tech-09）の物理層であり、将来の CP/M ラッパーのシリアル透過化の受け口でもあります。

設計で最も気を使ったのは決定論の維持です。ボードは環境変数 `XMIL_SERIAL` が文字デバイスを指すときだけ接続され、未設定時は「存在するが未接続」として、送信はスケジュールどおり虚空へ抜け、受信は決して届きません。既存の回帰スイートは誰もこのページを触らないため、ヘッドレス・決定的な実行には影響しません。

もう一つの設計判断は、ボーレートの効き先です。実転送は PTY の速度に委ね（PTY に実ボーレートの概念は無いため）、名目ボーレートは TxRDY／TxEMPTY の時間振る舞いにだけ効かせました。ゲストからは実チップと同じ待ち時間が観測でき、ホスト側の都合で転送自体は止まりません。

## 実装の要点

- コア実装（`io/usart.c`、新規）：EMM パッチと同型に、iocore のページ表へ 0x0C ページを登録します（全 ROM タイプ共通、機種条件なし）。ポートは 0x0C00＝データ、0x0C01＝制御（書）／ステータス（読）で、ページ内の他アドレスはこの2レジスタのミラーです
- レジスタモデル：リセット後の最初の制御書込みをモード語とする状態機械を実装し、コマンド語（TxEN／RxE／ER／IR）を処理します。ステータスは TxRDY（送信保持バッファ空き）、RxRDY（受信 FIFO 非空かつ受信有効）、TxEMPTY（保持バッファとシフトレジスタの双方が空き）、PE／OE／FE（ラッチ式。発生しうるのは FIFO あふれの OE のみ）、DSR（ホスト接続時に1）です
- 送信機は保持バッファ＋シフトレジスタの2段で、バイトは1フレーム分の時間が経ってからホストへ出ます。ホストが詰まればバイトはシフトレジスタに留まり、TxEMPTY は立ちません（実ワイヤと同じ振る舞いです）
- 受信は、レジスタアクセスのたびにホスト入力を 4KB の FIFO へ取り込みます。ポーリングループがそのまま搬送の駆動になります。RxE＝0 の間はホスト入力を読みません
- ボーレート：生成器クロック 153,600Hz 固定と置き、モード語の分周比が名目値を決めます（×16＝9,600 baud が標準）。ゲスト標準ドライバは ×16・8ビット・パリティ無し・1ストップ（モード語 0x4E）です
- ゲスト側ドライバ（`rs232c/src/usart.inc`）：初期化の定石シーケンス（0を3回→内部リセット→モード語→コマンド語 0x37）と、putc／getc／poll／stat を備えます。ポートが 0xFF 超のため、`(C)` レジスタ形式でアクセスします
- IOCS への実体化（ロードマップ26）：シリアルは新規エントリ 28＝SIN／29＝SOUT／30＝SPOLL として IOCS に組み込まれました。i8251 は遅延初期化（初回使用時に初期化）です。二層デバッガの下層・上層は自前のドライバを持たず、この IOCS 経由で通信します（dogfooding）
- 検証：PTY 越しの双方向テキスト送受信を実証しました。512バイトブロック＋ETX のエコーがバイト一致（取りこぼし無し）で、チェックサム行もホスト側計算と一致しています

## 原作との技術的差異

- チップ：作中のボードの搭載チップは i8251 で、再現側も同じチップのレジスタモデルを実装しました。この点は原作準拠です（第75話）
- I/O アドレス：作中に記載がありません。再現側は、xmil コアの I/O ページで全 ROM タイプ共通に空いていた 0x0C ページを選定しました（rs232c.md の決定記録）。0x0B は turbo 系でバンクメモリ、0x0D は EMM のためです
- ボーレート：作中に記載がありません。生成器 153,600Hz 固定＋分周で名目 9600 baud とする置き方自体が再現側の決定です
- ホスト接続：作中は実機＋実ケーブルですが、再現側は PTY（`XMIL_SERIAL`）です。実速度は PTY に委ね、名目レートはステータスの時間振る舞いにのみ効きます
- 同期モードと割込み：同期モードはセットアップ列の受理までで転送は未実装です。割込み駆動は対象外で、ポーリング前提です（8251 のピンは未結線扱い）。いずれも作中では不明の領域で、再現側の範囲設定です

## プリンタとパラレルポート（優先度を下げている理由）

- 作中では、プリンタへの印字制御そのものは描かれていません。パラレル（プリンタ）ポートが登場するのは主に対向リンクとしてで、第46話では X1 用プリンタケーブルを切断・クロス接続して X1⇔MBC-55 の双方向6ビット通信に流用しています。第73話で「パラレル通信の i8255 ボード化によりプリンタポートが空き、プリンタ接続が可能になった」旨の言及はありますが、印字の仕組みの記述はありません
- そのため再現側でもプリンタ対応の優先度を意図的に下げています。現行 IOCS にプリンタ出力コールはなく、エミュレータコア側にもプリンタエミュレーションはありません。ゲスト側プリンタドライバ（ロードマップ62）が将来の受け皿で、日本語ワープロ（ロードマップ45）の前提デバイスの一つとして後段に置かれています
- なお第46話式の6ビットパラレルリンク自体は通信手段として別扱いで、リモートデバッガの実機転送への差替先として tech-09 で触れています

## 数値まとめ

- ポート：0x0C00（データ）、0x0C01（制御／ステータス）
- 生成器：153,600Hz 固定、標準は ×16＝名目 9,600 baud（モード語 0x4E、コマンド語 0x37）
- 受信 FIFO：4KB
- IOCS エントリ：28＝SIN、29＝SOUT、30＝SPOLL（X1 は合計31エントリ）
- 公開：xmil-libretro コミット `dc52138`（RS-232C ボード追加）
