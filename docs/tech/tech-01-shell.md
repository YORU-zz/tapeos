# 技術解説01：シェル／モニタ

## 役割

シェル／モニタは TapeOS の常駐部です。起動直後からプロンプト `>` を出し、1文字コマンドでメモリ操作、ファイル読み書き、プログラム起動、テープ操作を行います。原作第51話の自己言及「OSといいつつ機械語モニタ＋α」が位置づけの正本で、本モジュールはその「モニタ＋α」そのものです。

## 実装の要点

- 起動：X1では互換IPLがFDのシステム領域（レコード1〜31）からシェル本体を0x2000へ読み、実行アドレスへ跳びます。シェルは起動時にIOCSテーブルを所定アドレスへ複写し、ワークページを初期化します
- コマンド：H（ヘルプ）、D（ダンプ128バイト）、E（バイト検査・変更）、M（バイト列書込）、G／J（実行。RETでシェルへ戻るのが契約）、F（ファイル一覧）、R（読込）、W（保存）、U（ドライブ切替）、I（RAMDISK初期化）、T（テープ読込）、S（テープ保存・新規）、A（テープ追加保存）、C（日時）、V（バージョン）、N（常駐イメージ操作、X1のみ）、X（常駐デバッグスタブ、X1のみ）です。詳細ヘルプと漢字表示はディスクプログラムHELP／KANJIに分離しています
- プログラム配置：通常プログラムは0x4000に置き、`R 名前`→`G 4000`で起動します。エディタやアセンブラはシェルに物理的に入らないため、この分離が前提です
- リロケータブル実行：TOSR形式のプログラムは、自己再配置スタブ（109バイト）がトレーラのマジックとチェックサムで自像を検出し、再配置ビットマップで上位バイトだけを書き換えてから入口へ落ちます。汎用ローダは存在せず、シェルは無改造のままです
- 予約席：X1シェル内には、カーソル表示フックの席128バイトと常駐Tiny Schemeの席128バイトが確保されています（存在と呼出し点が契約で、アドレスはビルド依存）

## 原作との技術的差異

- コマンド体系：原作後期のシェルはUnix風コマンド体系です（第80話。`ls`や`cat`、シリアルコンソールでは`login:`プロンプトの描写）。再現側のシェルは1文字コマンドの機械語モニタです。理由：再現対象がTapeOS世代（第51話「機械語モニタ＋α」）であり、Unix風の姿はROS世代のものだからです
- FD対応の経緯：原作ではFD対応はユーザーによるパッチ（雑誌記事）が先行し、後に公式FD対応版が作られました（第94話・第97話）。再現側は最初からFD対応のシェルとして実装しています。理由：再現は到達点の姿を対象とし、配布形態の歴史までは再現範囲に含めていないためです
- 動的RAMDISK再構成：原作のTapeOSは第47話時点で動的RAMDISK再構成つきと描かれます。再現側もIコマンドでブロック数を指定して再構成でき、作中の仕様（256バイトブロック、最大64KB、第19話）に合わせています。この点は原作準拠です
- シェルの世代交代：再現側では、シリアルIOCSやデバッガ改良の席を確保するため、Kコマンドと詳細ヘルプをディスクプログラムへ格下げし、本体を7,933バイトから7,733バイトへ圧縮しました（ロードマップ26）。原作に対応する記述はなく、再現側のサイズ事情による設計です

## 数値まとめ

- X1シェル本体：7,733バイト（上限7,936バイト＝FDシステム領域31レコード×256バイト）
- X1 4800版シェル：5,070バイト
- PC-8801本体：6,534バイト（上限7,936バイト）
- MZ-80Bモニタ本体：6,619バイト、MZ-80K：6,301バイト（X1式の上限は適用されません）
- スタック頂点：X1／PC-8801は0xE000、MZ両機は0xC000
- ワークページ：X1／PC-8801は0xE000台、MZ両機は0xC000台
- TOSR自己再配置スタブ：109バイト、完成像は256バイト超が必須
