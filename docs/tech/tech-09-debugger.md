# 技術解説09：デバッガ

## 役割と設計

デバッガは、TapeOS 上で動くプログラムを止めて中身を覗き、直して続行するための仕組みです。再現側には3つの形態があります。シェルに常駐するスタブ、単独で動くデバッガ RDBG、そしてホスト側プログラムとターゲット側スタブに分かれた二層リモートデバッガです。

設計の軸は「ターゲットに触れる部分を最小にし、賢い部分を外へ出す」ことです。Z80 にはシングルステップ機構がなく、命令長デコーダを常駐させる余裕もありません。そのためブレークポイントは RST 30H へのソフトウェアパッチ方式で、ヒット時に元のバイトを復元して自動解除するワンショットに統一しました。継続時は復元した命令をそのまま再実行するので、デコーダなしで正確に進められます。自己書き換えコードに対して安全なのも、この方式の帰結です。

## 実装の要点

- 常駐スタブ（X1 のみ、シェルの X コマンドで起動）：本体 1,668 バイトで、RAM 配置は空き領域 0xE900〜0xFFFF 内（メールボックス 0xEA00〜、スタブスタック 0xEB40〜0xEC00、レジスタ退避域 0xEC10）です。コマンドは D／M／R／B／G／C／Q／? の1文字体系です
- 実行中ターゲットの停止：G／C 実行中はサブ CPU のキー割込み（IM 1、ベクタ 0x38）を武装し、ESC キーで全レジスタを捕捉してスタブへ入ります（暴走ループの post-mortem 検査）。ESC 以外のキーはターゲットへ転送されます。ページ0にはブート時に 0x0030（BP）／0x0038（割込み）／0x0066（NMI、防衛的）へベクタを植えます
- メールボックス：エミュレータ環境では、ホストハーネスと共有する RAM 上のメールボックス（0xEA00、コマンド行48バイト＋捕捉出力256バイト）を「ケーブルの代わり」に使いました。スタブ本体は実機でもそのまま動く Z80 コードで、エミュレータ専用なのは転送の出入り口だけに局所化してあります
- 単独デバッガ RDBG：TOSR 自己再配置で任意アドレスに置ける単独プログラムです（本体 7,883 バイト＋再配置ビットマップ 986 バイト＋トレーラ 16 バイト＝イメージ 8,885 バイト）。起動時にページ0ベクタ9バイトを退避し、Q で全バイトを復元してからシェルへ戻ります
- 二層リモートデバッガ（ロードマップ26）：下層 RSTUB（1,971バイト、TOSD プログラム、0x4000 ロード）は画面に一切触れず、IOCS の SIN／SOUT／SPOLL 経由でプロトコル RDP/1 を話します。実行中だけページ0ベクタを借り、QUIT で復旧します。状態ミラーは 0xE660 です
- プロトコル RDP/1：フレームは SYNC（方向で 0xA5／0x5A）＋CMD＋LEN＋ペイロード＋CHK（CMD・LEN・ペイロード全バイトの XOR）です。コマンドは PING／READ／WRITE／SETBP／RUN／REGS／QUIT で、停止時は STOP フレームが非同期に届き、理由バイト（B＝ブレークポイント、I＝ESC 割込み、R＝RET 捕捉）と26バイトのレジスタブロックを運びます。このフレーム形式は WASM 展示のシリアルバックエンドの契約でもあります
- 上層 RHDBG：TinyBASIC プログラム（3,166バイト、関数11）＋機械語ヘルパ2つです。RHIO（217バイト）はフレーム化・チェックサム・再送（最大3回）・タイムアウトを担当し、RHFMT（73バイト）は16進ダンプ整形です。ヘルパ呼出は Tiny Scheme の `(call)` 経由（当時の USR ルーチンの型）です
- 上層の言語選定は実測で決めました。フレーム処理まで含む TinyBASIC 全実装案は 8,157 バイトで、関数数上限（FMAX 16）と実効サイズ上限（SCMCORE が 0x9000 に来るため、ファイル上限は実質 3,840 バイト）の両方に不適合でした。SmallC の全実装案も 8,593 バイトで E_BIG でした。最終構成は「対話と判断は TinyBASIC、バイトレベルの機械処理は機械語ヘルパ」という分割です
- 配置の発見：`(call)` はアドレスを15ビット fixnum で受け取るため 0x4000〜0xBFFF は死域で、当初 RHIO を置いた 0x7F00 では制御が迷走しました。最終的に RHIO は 0xD000、RHFMT はカーソル席 0x306E に置きました。フレームバッファには常駐 Scheme の席を暫定利用しています（いずれも予約席のスクラッチ利用として明記済みです）
- 検証：ホスト／ターゲットの2つのエミュレータプロセスを PTY で相互接続し、clean／garbage（ゴミ混入でも再同期）／flip（1バイト反転→NAK→再送で完走）／drop（回線切断でもホストがハングしない）の4モード全て PASS です。対象画面にはデモ自身の出力だけが残り、スタブの出力が一切無いことも確認しました

## 原作との技術的差異

- 二層デバッガの骨格と細部：原作第56話の二層デバッガについては、「シリアル経由」という骨格のみが原作由来で、フレーム形式（RDP/1）の細部は再現側の決定です（プロトコル仕様書が分類として明記しています）。本モジュール全体は再現側の味付けに分類されます
- 実機での転送方式：再現側のメールボックスはエミュレータ都合の代替実装です。実機では、出入り口を第46話式の6ビットパラレル転送ドライバ（プリンタポート出力＋ジョイスティックピン入力）に差し替えることで足りるよう、スタブ本体と転送を分離してあります（dbg-stub.md §2.2）
- 上層の言語：作中の第一候補どおり TinyBASIC を選びました。この点は原作の方向に沿っていますが、機械語ヘルパへの分割と配置（0xD000／予約席）は再現側のサイズ・アドレス事情によるものです

## 数値まとめ

- 常駐スタブ：1,668バイト、メールボックス 0xEA00（行48バイト＋出力256バイト）
- RDBG：イメージ 8,885バイト（本体 7,883＋ビットマップ 986＋トレーラ 16）
- RSTUB：1,971バイト、状態ミラー 0xE660
- RHDBG：3,166バイト（TinyBASIC、関数11）、RHIO：217バイト（0xD000 配置）、RHFMT：73バイト
- RDP/1：ペイロード最大255バイト、レジスタブロック26バイト、再送は最大3回
- TinyBASIC の実効ファイル上限（Scheme ゲート使用時）：3,840バイト
