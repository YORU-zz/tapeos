# 技術解説05：TinyBASIC

## 役割と設計

TinyBASIC は、TapeOS の第一の言語です。コンパイラ TBC とインタープリタ TBI の2本立てで、どちらもシェルから `r tbi` → `g 4000` の形で使う TOSD プログラムです。設計の土台は reloc-plan §5 で、作中の TinyBASIC を「X-BASIC の方言」として規定し、その §5.2 のサンプル骨格を文法の正本としています。

最大の設計判断は、フロントエンドの共有です。字句解析・構文解析・コード生成・ライブラリリンクまでの全体を1本の共有コア `tbcore.inc`（約9KB）にまとめ、TBC と TBI はドライバだけが違います。同じ文法・同じコード生成を2つの処理系で二重に保守しないための構成で、SmallC（tech-06）もこの型を踏襲しました。

もう一つの判断は、TBI をバイトコード VM ではなく「関数単位の遅延コンパイル（JIT）」にしたことです。理由は測定に基づきます。共有コアが約9KB で上限 10,240 バイトの大半を占め、別途バイトコード生成系と VM 実行系を同居させる余地がありませんでした。共有コアがそのままネイティブコードを出す以上、JIT が最も小さい、という結論です。

## 実装の要点

- 言語の形：プログラムは関数定義の集合で、行番号はありません。入口は `Main` です。型は `int`（16ビット符号付き）、`char`（8ビット符号なし）、`void` で、配列は `dim` で宣言するグローバル専用・1次元・定数サイズです
- TBC のパス構成：パス1でグローバル変数と関数シグネチャを収集し、パス2a（measure）でフレーム配置・関数オフセット・リテラル配置・ライブラリ使用集合を確定（コードは捨てる）、レイアウトでライブラリの依存閉包と配置を決め、パス2b（emit）で実バイト列を出力します
- 出力形式：TOSR v1（自己再配置スタブ109バイト＋本体＋再配置ビットマップ＋トレーラ16バイト）。生成コード内のアドレスはすべて絶対アドレスで埋め込み、フィックスアップ表は持ちません。代わりに、絶対アドレスのワードを書くたびに再配置ビットマップの該当ビットを直接立てます
- 呼出規約：引数はソース順にすべて2バイトスロットで push し、被呼側は IY フレーム（引数は IY 相対、ローカルは IY の下側）を使います。戻り値は HL です。グローバルは IX 相対です
- ライブラリ：`tblib.z80`（当初20ルーチン、630バイト）を ORG 0 と ORG 0x4000 で2回アセンブルし、差分から自己参照と相互参照を機械抽出します。コンパイラはプログラムが使うルーチンだけを依存閉包でコピーします。IOCS アドレスは絶対定数として再配置マークの対象にしません
- TBI の遅延コンパイル：プログラム骨格（ランタイム入口、関数スロット、ライブラリ）はロード時に配置し、関数は初回呼び出し時にその関数だけを measure → emit でコンパイルします。関数スロットは初期状態でスタブへの JP を持ち、JIT が戻りアドレスを退避・積み直しして関数の先頭へ跳ぶため、呼び側のスタックと引数は無傷で透過します。コンパイル系は IX／IY を一切使わないので、実行中のフレームを壊さずに割り込めます
- 検証上の一致：TBC と TBI は同一プログラムで同一の結果を返します（calc の15ワードで完全一致を検証）
- エラー：E1（構文）〜E10（型）の10種を `ERR LINE n Ek` と表示し、状態ブロック（0xE640）に結果を残します
- 形式バグの教訓：再配置実行を検証に入れたことで、「起点 0x8000 では動くのに再配置先で壊れる」形式バグ2件（スタブ即値の未書換え、ビットマップの基準ずれ）を検出して直しました

## 原作との技術的差異

- 文法と実在 X-BASIC の関係：実在の X-BASIC は中括弧ブロックや `and`／`or` キーワードを使いますが、本方言は reloc-plan §5.2 の骨格が正本であり、意図的に異なります。実在資料は参照のみで取り込んでいません（ライセンス方針による切り分けです）
- インタープリタの存在自体：作中の主人公はインタープリタを作りませんでした（面倒がってコンパイラで済ませた、という作者コメントが 2026-11-24 にありました）。したがって TBI は原作再現ではなく、再現側の味付けです。TBC（コンパイラ）の側が作中の系譜に沿います
- インタープリタ像の読み替え：reloc-plan §5.3 はインタープリタをプログラム単位の解釈と読める書き方ですが、本実装は「骨格は即時配置、関数は初回呼出時にコンパイル」という粒度に読み替えました（tinybasic.md §4 が明記しています）
- 演算子の意味論：`&&`／`||` は短絡評価しません（両辺を評価して 0/1 に正規化）。ゼロ除算は 0 を返します。どちらも暴走防止を優先する Tiny 仕様として明記した、再現側の意味論です
- 配列のサイズ解釈：`dim int a(N)` は要素数 N（添字 0..N−1）で、実 X-BASIC の N+1 方式からの意図的な Tiny 化です

## 数値まとめ

- 共有コア tbcore.inc：約9KB
- TBC：9,832バイト、TBI：9,524バイト（上限はいずれも 10,240 バイト。Scheme 呼出拡張後の最終値）
- ライブラリ tblib：当初20ルーチン・630バイト（Scheme 呼出の追加で24ルーチンへ拡張）
- TOSR 出力：起点 0x8000、スタブ109バイト、トレーラ16バイト
- 関数の for 制御領域：深さごとに4バイト × 最大8重
