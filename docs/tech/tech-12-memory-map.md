# 技術解説12：X1 TapeOS のメモリマップ

## 役割

この文書は、X1 版 TapeOS のメインメモリ配置を1枚にまとめたものです。アドレスと範囲は、契約の正本である interface-spec.md（§2 メモリマップ保証）と各モジュール報告書に出典のある値だけを使っています。配置は契約として固定され、契約チェック（EQU／TEXT 項目）が逸脱を検出します。

## 配置一覧（高位→低位）

- 0xE900–0xFFFF：常駐デバッグスタブ予約域（tech-09）。内訳はメールボックス 0xEA00–（MB_FLAG 0xEA00、署名 "DBST" 0xEA04、MB_LINE 0xEA10＝48バイト、MB_OUT 0xEA40＝256バイト）、スタブスタック 0xEB40–0xEC00、レジスタ退避域 0xEC10、ワーク 0xEC30–です
- 0xE800–0xE8FF：FNTBUF。Misaki フォントのセクタキャッシュ（256バイト、tech-11）です
- 0xE6E0：RDSIG。RAMDISK の証跡（"RD-OK"＋ブロック数）です
- 0xE6D0：KFSIG。漢字表示の成功マーカー "MSK8-OK" です
- 0xE500–0xE5FF：DIRBUF。TOSD ディレクトリセクタのコピー（256バイト、tech-03）です
- 0xE400–0xE45C：IOCS コール表（tech-02）。JP 命令×31エントリ＝93バイトです
- 0xE380：SUBBUF／TAPEBUF。E コマンド入力とテープ情報ブロック（34バイトバッファ）の共用域です
- 0xE368：TNAMEBUF（テーププログラム名13文字）。0xE358：NAMEBUF（FD ファイル名10文字）。0xE340：KBBUF（16バイトリング）。0xE300：LINEBUF（シェル行入力）です
- 0xE140：KEYLOG（受理キー記録、+0xE13F が件数）。0xE110：LASTCMD（最終コマンド行32バイト）です
- 0xE100：SIGADDR。起動署名 "TOS" の置き場で、常駐判定に使います
- 0xE000：STACKTOP。スタックはここから下向きに伸びます。0xE000 台全体がシェルのワークページです
- 0xD500：ツール用 DIRBUF。SmallC ツールのバイナリが大きくなったため、0xC800 以降のスクラッチの空き尾へ移したものです（tech-06）
- 0x9000–0xCFFF：メインメモリプール（拡張 IOCS、最大64ブロック×256バイト、tech-02）。ただし Scheme 呼出し使用時は同じ領域を SCMCORE が占有します（画像 0x9000–0xB3F8、cons アリーナ 0xB400–0xBA00、atom アリーナ 0xBA00–0xC000、文字列アリーナ 0xC000–0xC400、ゲート専用スタック 0xC400–0xC800、tech-07）。両者は排他な代替占有です
- 0x8000–：TOSR 形式プログラムの原点、およびアセンブル出力／ステージング域です。出力レンジガードの OUTMIN は 0x8000、X1 の OUTMAX は 0xE000 です
- 0x7000–0x7FFF：EDAS のソーステキスト（4KB）。0x6600–0x6DFF：EDAS シンボル表（128件×16バイト）。0x6400：EDIRBUF（自前ディレクトリコピー）です
- 0x4000–0x6800：通常プログラムの配置枠（10,240バイト）。NEWASM／SCED は自前 DIRBUF を 0x6800 に置きます。EDAS は 0x4000–0x7FFF をゾーンとして使います
- 0x4000：TOSD プログラムのロード先（tech-01）。シェルの R で読み、G 4000 で起動します
- 0x2000–0x3E35：シェル本体（LOADADDR 0x2000、現行 7,733バイト、上限 7,936バイト）。本体の中にカーソル席 0x306D／0x306E と常駐 Scheme 席 0x30EB が含まれます
- 0x0000–0x1FFF：起動直後は互換 IPL の領域で、ブート後に切り離されます。デバッグスタブは RST ベクタ 0x0030／0x0038／0x0066 をここへ設置します

メインメモリの外にある記憶域も、配置の一部として記します。

- EMM（I/O ポート 0x0D00–0x0D03 でアクセスする別メモリ、デバイス裏付け1MB）：バイトアドレス 0x00000–0x0FFFF が RAMDISK（ブロック0＝ディレクトリ、1–＝データ）、0x10000–0x1BFFF が SCED のテキストバッファ2面（各24KB）、0x1C000 以降は未割当てです
- I/O 空間：RS-232C ボードは 0x0C00（データ）／0x0C01（制御・状態）です（tech-10）

## 機種差の注記

- IOCS 表は MZ-80B／MZ-80K では 0xC400 です（X1／PC-8801 は 0xE400）
- 本体ロード先は機種ごとに違います。MZ-80B は 0x0000、MZ-80K は 0x1000、PC-8801 は 0xC100 です
- ワークエリアは全機種で同型オフセットに置かれますが、ページが違います（X1 は E ページ、MZ 両機は C ページ、PC-8801 は 0xE100–0xE8FF）。起動署名は MZ 両機では 0x9200 です
- RAMDISK は X1 のみ EMM 裏付けで、他機種は実 RAM の2セグメント構成になり、容量がクランプされます（MZ-80B 96ブロック、MZ-80K 80ブロック、PC-8801 68ブロック）
- メインメモリプールと RS-232C ボードは X1 のみの要素です

## 原作との技術的差異

- IOCS コール表の配置
  - 原作側：作中では 2000H 番台への配置が描かれます（差異インベントリ #2、展示由来文書に開示済み）
  - 再現側：機種ごとに固定です（X1 0xE400、MZ 0xC400）
  - 理由：呼出アドレスは全バイナリに焼き込まれるため、展示前の移行は行わず、作中側レイアウトの最初の消費者が現れた時点で移行する方針が決定済みです
- RAMDISK の 64KB
  - 原作側：第19話で 256バイトブロック×最大256＝64KB とされ、第47話で動的再構成が描かれます
  - 再現側：X1 では EMM という別メモリの裏付けで 64KB を実現します。他機種は実 RAM の空きが足りず、容量をクランプして正直に報告します
  - 理由：作中の 64KB は EMM 相当の別メモリあっての値で、実 RAM しかない機種では物理的に確保できません
- メインメモリプール 0x9000–0xCFFF
  - 原作側：第31話の「メインメモリ管理の RAMDISK 共通化」です
  - 再現側：EDAS ゾーンとワークページの間の連続空き領域に、再現側で初めて導入する FAT 方式のブロック管理として実装しました
  - 理由：作中に管理方式の詳細はなく、置き場所は空き領域の都合で決まります
- プログラム領域 0x4000
  - interface-spec.md §2.3 が明記するとおり、この値自体に作中典拠はありません。根拠があるのは分離の必然性だけで、シェルのサイズ上限（FD システム領域の制約で 7,936バイト）にエディタとアセンブラが物理的に入らないため、別ファイルのプログラムとして 0x4000 に置く形になりました
- RS-232C ボードの I/O アドレス
  - 原作側：第75話で確認できるのはチップが i8251 であることだけです
  - 再現側：0x0C00／0x0C01 を選定しました
  - 理由：I/O アドレスは作中に無く、ページ 0x0C が全 ROM タイプ共通で空いていたためです

### 根拠未確認の差異

- ワークページ（0xE000 台）や起動署名 0xE100 の配置そのもの：出典資料に作中側の対応記述が見当たらず、再現側の設計としてのみ確認できます。作中にも配置の指定があるかどうかは未確認です

## 数値まとめ

- シェル本体：0x2000 ロード、7,733バイト（上限 7,936バイト）
- IOCS 表：0xE400、31エントリ×3バイト
- プログラム枠：0x4000–0x6800（10,240バイト）、EDAS ゾーンは 0x4000–0x7FFF
- プール／SCMCORE 域：0x9000–0xCFFF（排他）
- スタブ予約域：0xE900–0xFFFF
- RAMDISK：EMM 0x00000–0x0FFFF（64KB）。SCED バッファ：EMM 0x10000–0x1BFFF
