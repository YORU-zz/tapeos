# 技術解説06：SmallC

## 役割と設計

SmallC は、TapeOS の第二の言語として実装した C サブセットの処理系です。コンパイラ SCC とインタープリタ SCI の2本立てで、TinyBASIC（tech-05）の設計を土台にしています。共有フロントエンド（字句解析・構文解析・コード生成・ライブラリ結合・TOSR 出力）を `sccore.inc` にまとめ、SCC と SCI はドライバだけが異なります。生成コード規約（IX＝ヒープ、IY＝フレーム、引数はソース順に push、戻り値は HL）も TinyBASIC と同一です。

設計の出発点は「サブセット確定表」です。C の何を採り何を落とすかを、理由とともに着手時に確定しました。落とした主なものは、ポインタへのポインタ（使用場面が薄い）、struct／union／enum／typedef（Small-C の範囲外）、float／double／long（16ビット整数のみとする）、初期化子（TOSR イメージに初期化データ領域を持たない設計のため）、switch／goto（構造化制御と if 連鎖で代替できる）、関数形式マクロと条件付きコンパイル（サイズ予算）です。逆に、時代のコード資産に多い K&R 形式の関数定義と暗黙の int は受理します。

## 実装の要点

- 型：`int`／`char`／`void`、1段ポインタ（`int*`／`char*`）、1次元配列（定数サイズ、グローバル／ローカル両方）です。char は読み出し時にゼロ拡張、格納時に切り詰め、演算は int へ昇格します
- 文と式：複合文、if／else、while、do／while、for、break、continue、return を備え、式は代入（複合代入を含む）、条件演算子、ビット演算・シフト・比較・算術の全階層、前置／後置 ++／--、間接参照とアドレス取得、キャストまで実装しています。除算・剰余は符号付き（C の切り捨て規則）で、ゼロ除算は 0 を返します（ライブラリ規約、TinyBASIC と同一）
- プリプロセッサ：`#include`（入れ子2段まで、TOSD ディレクトリから読む）と、オブジェクト形式の `#define`（最大10個、置換文字列31バイトまで）だけを実装しています。自己参照マクロは展開段数上限（4段）で E_PP エラーにします
- ライブラリ clib：算術補助と IOCS 外部関数（puts／printf／getchar／input／locate／cls／inkey／stick／vsync／peek／poke／putchar）の20ルーチン、932バイトで、使用分だけがリンクされます。printf は %d %u %c %s %% に対応し、戻り値は 0 固定です（文書化した制限）。Scheme 呼出の追加で24ルーチンになりました
- SCI の JIT：TinyBASIC の TBI と同じく、関数スロットに JP スタブを置き、初回呼出時にその関数だけを measure＋emit して差し替える per-function lazy JIT です。全サンプルで SCC のコンパイル実行結果と SCI の JIT 実行結果が完全に一致しました
- ツール内部マップ：C コンパイラは既存ツールの 10,240 バイト枠に収まらなかったため、EDAS の先例に倣い文書化した内部マップを採用しました。バイナリは 0x4000 から、DIRBUF は 0xD500（Scheme 拡張で肥大したための移動）、出力イメージは 0x8000 に置きます
- 変換ツール bascvt.py：TinyBASIC と Small-C の共通サブセット上で相互変換するホスト側ツールです。変換できない構文は黙って落とさず、レポートに行番号付きで列挙して終了コード1を返します。合格条件はテキストの同一性ではなく、双方向変換後の実行結果の一致です（corpus 3組で6通りの実行結果が全て一致）

## 原作との技術的差異

- `&&`／`||` の短絡評価：SmallC は短絡評価します。これは TinyBASIC（短絡しない）とは意図的に異なる点で、C の慣習を優先しました（smallc-tos.md のサブセット確定表が明記しています）。同じプロジェクト内の2言語で意味論が違うため、変換ツール bascvt はこの差を変換時の注意として扱います
- エントリ関数名：SmallC は小文字の `main` です（TinyBASIC の `Main` と異なる）。これも C の慣習に従った再現側の決定です
- ポインタ比較の符号付き性：ポインタの比較は符号付きで行うため、0x8000 以上のアドレス同士の大小比較は符号なしとは一致しません。既知の制限として文書化しています
- printf の戻り値 0 固定、getchar に EOF が無いこと：いずれも文書化した制限で、C 本来の意味論からの差異です

## 根拠未確認の差異

- 作中における C 言語処理系の位置づけ：本モジュールは再現側の言語基盤整備として実装したもので、作中の特定の話数に対応する処理系としての根拠は、参照した報告書の範囲では確認できていません

## 数値まとめ

- SCC：12,899バイト、SCI：12,856バイト（上限 13,056 バイト＝ツール内部マップによる）
- clib：932バイト、20ルーチン（Scheme 呼出の追加後は24ルーチン）
- 出力イメージ：0x8000、上限 15,872 バイト
- プリプロセッサ：#include 入れ子2段まで、#define 最大10個・置換文字列31バイトまで、マクロ展開は4段まで
- シンボル表：0x7600〜0x7EFF（当初マップ）
