# 技術解説08：ツール群

## 役割と設計

ツール群は、エディタとアセンブラ、逆アセンブラの一群です。シェル本体には物理的に入らないため、いずれも 0x4000 に置く TOSD プログラムとして分離されています（配置枠は 0x4000〜0x6800＝10,240 バイトが古典ツール枠。ただし EDAS ゾーンとして 0x4000〜0x7FFF が予約扱いで、ツールごとに文書化した内部マップを持つものがあります）。

系譜は、土台のアセンブラ EDAS から枝分かれしています。EDAS のファイル層（TOSD の読み書き作法）が共通基盤になり、NEWASM はその再設計、SCED は EDAS とファイル形式を完全互換にしたエディタ、MCED は SCED の層を継承した別系統のエディタ、DISASM／EDIS は逆アセンブラの単体版と EDAS 組込版です。「同じディスク形式・ファイル形式で相互に読み書きできる」ことが、ツール群全体の設計契約です。

## 実装の要点

- EDAS（エディタアセンブラ）：ソーステキストを 0x7000〜0x7FFF（4KB）に保持し、シンボル表は128件×16バイトです。後に `Z` コマンド（逆アセンブル起動）が追加され、本体は 8,317 バイトになりました。TOSR 版（EDASR）は 9,133 バイトです
- NEWASM（次世代アセンブラ、7,118バイト）：EDAS と意図的にアーキテクチャを変えています。ソースは全体を RAM に保持せずパスごとにセクタ単位で読み直すストリーミング方式（ソースサイズの上限はディスク容量のみ）、シンボル表は単方向リンクリスト、再配置のマーク付けはフィックスアップリスト方式です。4機種マスタでビルドし、MZ-80B 版と MZ-80K 版はバイト同一です
- SCED（スクリーンエディタ、8,462バイト）：第15話の自作スクリーンエディタの再現です。モードは NORMAL／INSERT／COMMAND の3つを持つ tiny-vim サブセットで、検索・置換・ビジュアルモードなどは意図的に切り捨てました。テキスト管理は行毎ディスクリプタ（8バイト×最大256行）とアドレス昇順フリーリスト（隣接結合）で、テキスト実体は EMM 上 24KB×2 バッファです。バッファ切替で保存を強制しない（未保存変更を保持したまま往復できる）のが仕様です
- SCED の描画と入力：IOCS の CONOUT は 0x7F 以上を落とすため、画面はテキスト VRAM への直接書き込みで描きます（属性は下位3ビットのみ安全）。日本語入力は SKK 風ローマ字→半角カタカナ変換で、濁点・半濁点は独立コード 0xDE／0xDF として格納します（tech-11 参照）
- MCED（MicroEmacs 風エディタ、10,229バイト）：SCED とは別プログラムです（単一バイナリのエイリアス化はユーザー判断で不採用）。テキスト層・ファイル層・描画・SKK 変換・undo コアは SCED のソースから splice でそのまま取り込み、コマンド層だけをモードレスな Emacs 風に置き換えました。キルバッファは EMM 0x1C000 に 8KB、バッファ状態ブロックはマークとゴール列の追加で33バイトに拡張しています。サイズ枠に収めるため、C-u リピートカウント、リージョン操作の undo、検索のラップアラウンド、ウィンドウ分割は意図的に切り捨てました
- キーボード由来の逸脱（MCED）：X1 のサブ CPU は CTRL+SPACE をコード0と報告するため C-SPC／C-@ は到達不能で、マーク設定は ESC SPC に変更しました。C-_ も本環境では生成不能で、検証済みの undo 経路は C-x u です。いずれもプローブで実証した上での決定です
- DISASM（逆アセンブラ、5,713バイト）：テーブル駆動ではなく、オペコードを x／y／z／p／q ビットフィールドに分解する構造デコードを持ちます。ラベルを必ず歩行境界に置けることを、ドライウォークを反復する固定点ループで保証します。再アセンブルで同一バイトに戻らない非正規エンコーディングは、ニーモニック化せず DB として出して次バイトから再同期する方針で、ラウンドトリップ（逆アセンブル→再アセンブル→バイト一致）を合格条件にしています
- EDIS（EDAS 組込逆アセンブル、モジュール 5,934バイト）：当初は EDAS 本体内蔵を目指しましたが、本体の残量（TOSR 版で83バイト）が足りず、「EDAS に Z コマンド（+181バイト）を追加し、実体は TOSD ファイルの EDIS モジュールを 0x4000 へ読み直して実行する」形に分離しました。単体版 DISASM は分割後もバイト同一に再構築できます

## 原作との技術的差異

- SCED のテキスト置き場：作中（第15話）の設計は GRAM 常駐ですが、X1 の GRAM はセルアドレス方式の表示メモリで線形ストアとして使えないため、テキスト実体は EMM に置きました。これが唯一のハードウェア都合の読み替えです（sced.md §1.2）。行管理とフリーリストの設計そのものは原作踏襲です
- SCED／MCED という名前：作中のエディタに固有名はなく、どちらもプロジェクト内名称です。MCED は、作者（辺根除音さん）が小説のスクリーンエディタのモデルとして挙げた MicroEmacs をイメージしたもので、作中に同名のプログラムがあるわけではありません
- 逆アセンブラの実装順序：原作では EDAS 内蔵が先行し単体版が切り出された順序ですが、再現側ではユーザー決定（2026-11-24）により単体版 DISASM を先に作り、次に EDAS へ組み込みました（disasm.md）
- PCG 全角ひらがな表示の見送り：作中では表示ルーチン側（第14話の表示 ABI）の仕組みですが、再現側のエディタには入れていません。理由は tech-11 にまとめています
- MZ 系へのエディタ移植：作中の EDAS 往復（第19話）は MZ-80B 上の話ですが、エディタ自体の初出は第15話（X1）であり、本段階では X1 実装＋EDAS 往復の実証を完了条件として、MZ／PC-8801 への移植は見送りました（sced.md §6）

## 数値まとめ

- 配置：0x4000、古典ツール枠 10,240 バイト（0x4000〜0x6800）
- EDAS：8,317バイト（Z コマンド追加後）、EDASR：9,133バイト、シンボル表128件、ソース保持 4KB
- NEWASM：7,118バイト（全機種同サイズ）
- SCED：8,462バイト、行上限256行・行長80文字、テキスト 24KB×2 バッファ（EMM）
- MCED：10,229バイト、キルバッファ 8KB（EMM 0x1C000）
- DISASM：5,713バイト、入力範囲上限 16,384 バイト、ラベル表 1,024 件
- EDIS：5,934バイト（全機種同一レイアウト）
