# 技術解説11：漢字・フォント層

## 役割と設計

漢字・フォント層は、TapeOS で日本語を表示するための部品群です。X1 のテキスト画面は ANK 前提で、漢字を出すにはフォントデータをどこからか供給し、グラフィック画面へ描く必要があります。

設計の要点は、漢字表示を IOCS の文字列コールとしてではなく、「フォントファイルを FD から読み、GVRAM へ描くプログラム層」として実装したことです。グリフの取得は既存の IOCS DREAD（ディスク読み）に乗り、フォント差し替えや機種差をプログラム側で吸収します。フォントデータの出自は美咲フォント（門真なむ氏）で、クレジットと条件を公開物の NOTICE に明記しています。

エディタ側の日本語入力は、漢字ではなく半角カタカナを採りました。当時の実装慣行に沿い、SKK 風のローマ字変換で JIS X 0201 半角カタカナコードをテキストに格納します。表示側のシステムフォントがそのコード範囲にグリフを持つため、特別な描画経路なしに読める形で表示できます。

## 実装の要点

- フォントファイル MISAKI8：美咲フォントの BDF から生成ツール（mkfont.py）で作る FD 上のファイルです。JIS X 0208 の 8×8 グリフを収め、グリフの位置は 16＋((区−1)×94＋(点−1))×8 のオフセット式で決まります。グリフはセクタをまたがない配置です
- KANJI プログラム：ディスクプログラム（739バイト、0x4000 ロード）として日本語テキストを表示します。グリフは IOCS DREAD でオンデマンドに取得し、1セクタ分のキャッシュ（FNTBUF、0xE800）を持ちます。描画はテキストセルの下に GVRAM へ 2倍角（16×16ピクセル＝2×2テキストセル）で、白は3プレーン全点灯です。成功時には KFSIG（0xE6D0）に "MSK8-OK" が残ります。フォントファイルが無い、またはヘッダが不正な場合はエラーを表示して終わります
- 常駐からの格下げ：漢字表示は当初シェルの K コマンド（約643バイト）でしたが、ロードマップ26のシェル圧縮で TOSD プログラム KANJI へ分離されました（詳細ヘルプの HELP 分離と同時です）
- ANK 側フォント FNT0808.X1：meister68k 氏の X1 互換フォントで、データは美咲フォント由来です。0xA1〜0xDF に半角カタカナのグリフを収めており、エディタの半角カタカナ表示はこのグリフに支えられています。リポジトリには同梱せず、利用者が配布元から入手して配置します
- MZ 側のフォント：MZ の FONT.ROM も同じ美咲フォント BDF から生成しています（環境再現の部品表に記録があります）
- エディタの SKK 風変換（SCED／MCED 共通）：ローマ字を半角カタカナコードとして格納し、濁点・半濁点は後続の独立コード 0xDE／0xDF です。子音＋母音のグリッド、拗音、二重子音＝っ、`n` の扱い（子音の前・末尾では ん）まで規則化し、未確定文字列はステータス行に表示します。表示はテキスト VRAM 直書きのため、カナを含む画面でもそのまま出ます

## 原作との技術的差異

- 日本語コンソールの方式：原作（第60話）では、ビットマップ日本語コンソール（行数・桁数可変）は IOCS の文字列ドライバだけを差し替えて実現されます。再現側はこの方式を採らず、拡張 IOCS とグラフィックドライバの組み合わせで実現する方針に決定しています（2026-11-23 の決定、ロードマップ42）。現行の KANJI プログラムは、その方針が入る前の、プログラム層による表示です
- PCG 全角ひらがな表示：作中では表示ルーチン側（第14話の表示 ABI）の仕組みですが、再現側のエディタには入れていません。理由は3点です。(1) 本環境では半角カタカナが CG フォントのグリフで既に読める形で表示でき、作中の PCG 展開が前提とする「カタカナを表示できない表示経路」という前提が崩れていること。(2) 全角展開はエディタの仕事ではなく表示 ABI の仕事で、それ自体が独立した表示側プロジェクトになること。(3) エディタ側の契約（ローマ字変換とカナコードの格納）は実装済みで、将来表示 ABI 側に全角展開が入ればテキストは無変更で使えること（sced.md §1.8）
- 漢字表示の置き場所：シェル常駐からディスクプログラムへの分離は、再現側のシェルサイズ事情によるもので、作中に対応する記述はありません

## 数値まとめ

- グリフ：8×8ドット（JIS X 0208）、描画は 16×16 ピクセル（2倍角）
- KANJI プログラム：739バイト（0x4000 ロード）、旧 K コマンド一式は約643バイト
- フォントキャッシュ FNTBUF：256バイト（0xE800）、成功マーカー KFSIG：0xE6D0
- 半角カタカナ：JIS X 0201、0xA1〜0xDF、濁点 0xDE／半濁点 0xDF は独立コード
