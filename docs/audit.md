# 監査（全スイート回帰）の方法と結果

本プロジェクトでは、インターフェースに触れる変更や節目の時点で
「監査」と呼ぶ全スイート回帰を行い、合格したものだけを暫定公開
しています。本書は、その方法と、これまでの結果の要約です。
個別の作業ログは含みません。

## 方法

監査は次の3層で構成します。

1. **契約チェック**（常時・高速）：インターフェース仕様
   （`docs/interface-spec.md` §7）の機械チェック可能な部分を、
   基準値との照合で検証します。内容は、成果物バイナリの
   sha256 バイト同一性（HASH）、IOCS ジャンプテーブル
   テンプレートのバイト同一性（IOCS）、メモリマップ等の
   インターフェース定数（EQU）、ソース中の固定リテラル
   （TEXT）、コンポーネントのサイズ上限（SIZE）です。
   本リポジトリでは `tools/contract-check.sh` が X1 公開範囲の
   抜粋（HASH 6 件・IOCS 2 件・EQU 31 件・TEXT 3 件・SIZE 5 件）
   を、開発ツリー側では全機種を対象とする完全版（HASH 179 件・
   IOCS 5 件・EQU 58 件・TEXT 3 件・SIZE 16 件）を実施します。
   両者の期待値は一致しています。
2. **全スイート回帰**：機種別ビルド（X1／MZ-80B／MZ-80K／
   PC-8801）と、言語系（TinyBASIC／SmallC／Tiny Scheme）、
   ツール系（EDAS／NEWASM／SCED／MCED／DISASM／EDIS）、
   テープ相互運用、二層リモートデバッガ等の各テストスイートを
   一括実行し、全ユニットの合格を確認します。エミュレータ上で
   の実際の動作・画面表示・タイミングはこの層でのみ確認され
   ます（契約チェックの範囲外です）。
3. **バイト同一性の照合**：変更対象外の機種・プログラムに
   ついて、ビルド成果物が基準とバイト単位で一致することを
   確認します。インターフェース変更が正当な場合は、仕様を
   更新し、関係スイートを再実行したうえで基準値を再生成し、
   その内訳を記録します。

## 結果の要約

- 2026-11-24、二層リモートデバッガの完成に伴う監査で、
  全 24 ユニットが合格しました。この際に X1 の IOCS 拡張
  （31 エントリ化）等の正当なインターフェース変更を反映し、
  契約ベースラインを再生成しています（EQU 58 件体制）。
- 本リポジトリの暫定公開スナップショットは、いずれも監査
  合格後に公開されたものです。公開後に発覚した不整合は、
  次回監査の検査項目へ還元する運用にしています
  （`docs/interface-spec.md` §8 が、その受け皿です）。
- 現在の契約チェックは、開発ツリー側・本リポジトリ側の
  双方で合格しています。

## CI との関係

GitHub Actions の CI は、ビルドの成功、契約チェック（公開範囲
の抜粋）、ROM 台帳チェック、および主要生成物のサイズ／
ヘッダーの妥当性を自動で確認します。全スイート回帰（監査
そのもの）はエミュレータ実行を含むため、開発側で節目ごとに
実施します。
